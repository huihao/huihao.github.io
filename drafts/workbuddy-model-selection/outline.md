## 一、定位

- **读者**：办公室里天天让 AI 干活、但只知道「积分在掉」的人。没摸过模型档位，也没看过自己这个月的账单。

## 二、核心主张（正文必须逐条兑现）

1. **三档不是"弱/中/强"三个模型，是三套由系统调度的档位。** 模型选择器里上方三档（快速/均衡/极致）与下方内置模型是**并列两排**，选一个，不叠加。
2. **积分账单里波动最大的变量是上下文长度。** 官方文档原话：「更大的窗口不会让模型变聪明，只会让每轮消耗成倍增加。」每一轮都要把整段上下文重发一遍。
3. **省积分的顺序有先后：先断上下文，再谈降档。** 新开会话 > 上下文档位 > 经济模式 > 思考强度 > 最后才降档位；降档是最容易做、收益反而排在后面的一步。（此排序参考第三方测算的结论，正文标注来源）

## 五、正文结构

### 0. 黄金三行（≤150 字进入正题）
- 第 1 句给冲突：同样问一句「帮我整理会议纪要」，在快速和极致档上花的积分不是一回事，但没人告诉你是 3 倍还是 6 倍。
- 第 2 句给依据（A 级）：官方文档写明，消耗量＝模型 Token 定价 × 任务复杂度，且每轮都要完整重发上下文。
- 第 3 句给承诺：这篇给一张对照表、四个开关，和一条省积分的先后顺序。
- 素材：`sources.md` A2 / A1 / C1

### 1. 模型选择器里有两排选项，别当成一层（≈300 字）
- 上面一排是三档（快速/均衡/极致），由系统在下层模型池里调度；下面一排是可以手动点名的内置模型。
- 两者是「选一个」的关系，不存在"档位系数再乘模型倍率"。
- 关键认知：选档位＝把调度权交出去（换取稳定和封顶的价）；选具体模型＝自己点名（更可控，但价格由那个模型自己算）。
- 配图：`assets/model-mode.9NY4y8fJ.png`（说明：模型选择器顶部三档）

### 2. 三档各自接什么活（≈400 字）
- 官方定位原文三行：快速（简单明确：日常问答、格式转换、小段代码修改、文案润色）／均衡（绝大多数任务：写文档、分析数据、多文件代码改动）／极致（跨模块重构、多步骤推理、要反复验证的分析）。
- 我的补充判断（落地层）：快速档的正确用法是"一次成型的小活"；均衡档承接"结构固定、量不小"的活；极致档留给"错一次就要返工"的活——终稿核对、跨文件改动、逻辑链条长的问题。
- 第三方测算（标注 C 级，注明作者自述"官方未逐条公示"）：快速 0.21 / 均衡 0.65 / 极致 1.20；均衡相对快速 3.10 倍，极致相对均衡 1.85 倍。
- 由此得出：**从快速升到均衡的那一步最贵，从均衡升到极致反而便宜**——日常停在均衡，关键任务再上极致，是性价比最高的走法。
- 配图：竖排卡片「任务类型 × 档位」（避免宽表）

### 3. 现在能点名的 14 个内置模型（≈400 字）
- 表格（转竖排卡片）：Hy4 preview（混元新一代）、Hy3（混元思考）、GLM-5.3（1M 上下文）、GLM-5.3-Flash（快速版）、GLM-5.2（1M，长程）、GLM-5.1（均衡日常）、GLM-5v-Turbo（多模态）、MiniMax-M3（多模态，代码与智能体）、MiniMax-m2.7（均衡性价比）、Kimi-K3（复杂长程自主任务、前端强）、Kimi-K2.7-Code（面向编程）、Kimi-K2.6（日常多模态）、Deepseek-V4-Flash（1M，速度优先）、Deepseek-V4-Pro（1M）。
- 一句选型提示：看三件事就够——支不支持图片输入、支不支持思考模式、要不要 1M 上下文。
- **模型清单在变**：腾讯云企业版文档（2026-09-07 更新）里的清单还是 Auto、Hy3、GLM-5.2 一代，和个人版当前这版对不上；别照着两三个月前的文章抄。（A1 + A10）

### 4. 积分到底怎么扣（≈400 字）
- 官方两条因素：模型 Token 定价（高级模型单价更高）× 任务复杂度。
- 加一条很多人忽略的：单轮消耗随上下文体积涨，官方原文「更大的窗口不会让模型变聪明，只会让每轮消耗成倍增加」。
- 额度（官方定价表）：体验版 500 积分/月（免费）｜标准版 99 元 = 4000｜高级版 199 元 = 9000｜旗舰版 999 元 = 50000；加量包 1000 积分 / 50 元 / 1 个月，不支持退款。
- 两条容易踩的规则：赠送积分自到账日起 1 个月内有效、积分按月发放不结转；WorkBuddy 与 CodeBuddy 同账号积分共享。
- 扣减顺序：先扣最先到期的，到期时间相同先扣基础积分再扣赠送积分。
- 想看明细：官网个人中心 → 套餐与用量（客户端头像 → 设置 → 套餐与积分只看得到套餐）。
- 配图：自绘「账单构成」示意图（哪些部分乘在一起）

### 5. 四个开关，这一段是文章主干（≈600 字）
每个开关统一写四件事：**官方定义 → 它影响什么 → 什么时候该动 → 图**。
1. **新会话代替补丁**（官方技巧 7）：会话一长，前说后忘还烧积分；把关键背景重新简洁说一遍更划算。成本：重复交代背景的力气。→ 图：`assets/model-context.B_hqhlU2.png`
2. **上下文档位**：点输入框「上下文用量」圆环 → 底部切 默认 / 适中 / 超长；档位越高单轮积分越多；切换即时保存、对话中下一轮生效、**只对当前任务生效**，切模型或新建任务就回到默认。→ 图同上
3. **经济模式**：设置 → 智能体 → 经济模式（个人版默认开启）；开启后系统在合适时机自动压缩上下文；关闭后保留完整上下文、细节不丢，但长对话消耗明显增加。**注意原 Max 模式开关已经搬到这里了**，老文章的路径会失效。→ 图：`assets/setting-economy-mode.BpxtJUky.png`
4. **思考强度**：模型给答案前的推理投入，等级取决于模型支持档位，默认已选好、多数场景不用动；会长逻辑链、易出错的活才往上调。会话标题自动生成是轻量辅助调用、不开思考模式，省的那部分 Token 就是这么来的。→ 图：`assets/model-thinking.B4oE7CN7.png`
- 收尾一句：默认不动这四个开关的人，多半在快速档和均衡档之间来回横跳，积分却按最贵的那条路径扣。

### 6. 按任务查表（≈400 字）
- 场景 × 建议（竖排卡片，办公场景优先）：改格式/改错字/短问答 → 快速；会议纪要、周报、数据分析、多文件改动 → 均衡；终稿核对、跨文件重构、长链条推理 → 极致；长文档精读 → 1M 上下文档模型（GLM-5.3、GLM-5.2、DeepSeek V4 系列）；截图与图表识别 → 支持图片输入的轻量模型；批量改写 → 快速或直选轻量模型。
- 补一句故障排查（官方 FAQ）：读不了图片/PDF/Excel/Word，通常是当前模型不支持该文件类型，换模型即可。

### 7. 几个坑（≈350 字）
- 上下文档位只对当前任务生效，换模型就回默认——以为"设一次管全程"会多吃积分。
- 模型下线后会自动切到同系列新模型，但**思考强度和上下文档位不沿用**，会回到新模型的默认值。
- 自定义模型没配接口地址或 API Key 会在选择器里置灰，发请求时报 4100；本地 Ollama 不需要 API Key，不受影响。
- 接第三方模型的费用你自己付，不走 WorkBuddy 积分。
- 模型会"极度拥堵"，此时换模型比等更快（红色图标在列表里就能看到）。
- 网上流传的模型倍率表（如 0.21/0.65/1.20、各模型倍率）是第三方按客户端配置推算的，官方没有逐条公示，且清单是 2026-10 的快照，对照着用。

### 8. 什么时候该自己接模型（≈250 字）
- 腾讯云 Token Plan（兼容混元/MiniMax/Kimi/GLM）、Coding Plan、本地 Ollama（默认 11434 端口，兼容 OpenAI 协议）。
- 价值：敏感数据不出本机；本地推理不消耗 WorkBuddy 积分；离线可用。代价：算力自备、模型效果自己评估。
- 定制的前提是自定义模型配置只存在本地 `workbuddy/models.json`，API Key 不上云。

### 9. 结尾（≈200 字）
- 三到五条可带走的总结（不超过 5 条，每条一句话，不写"综上所述"）。
- 一个开放问题引出 CTA。
