## 五、排版微调

**1. 加粗收敛。** 正文现在有 147 处加粗（表格内另有 13 处，转成卡片后只剩公司名）。手机上满屏加粗等于没有重点。建议：

- **保留**：含数字或百分比的 28 处（`90%+ 的代码由 AI 生成`、`31 万行`、`117 个疑似问题`、`67.8 万行 WARN 日志`、`16%`、`6.1%`、`51%`、`40%` 等），这些是证据；
- **保留**：6 句带引号的原话（美团"当 90% 代码由 AI 生成……"、虎嗅"一个高级程序员之所以存在……"、晚点"先用 AI 替代别人，被默认是自己留下来的最好理由"、毕玄"不再按技术栈划分技术岗位……"、Harness 篇"监控一片绿，没有一条告警"、Harness 篇"格式漂亮、结论全错"）；
- **去掉**：其余约 110 处结论性加粗，改成正常字重即可——句子本身已经足够短，不需要再喊一遍。

判定规则很简单：**一句话里如果同时有数字和结论，只加粗数字；如果只有结论没有数字，就都不加粗。**

**2. 引用块。** 12 段 `>` 引用（其中三段各含多句）在微信里默认渲染成灰色小字，容易被划过去。改法：把其中 7 段最有力的做成带竖线的引用卡片，其余降级成灰色普通段落。自动转换脚本 `scripts/wechat-draft.mjs` 里的 `HERO_QUOTES` 列出这 7 段的判别词：

**3. 小标题层级。** 10 个 `##` + 8 个 `###`，在微信里层级太深。公众号习惯只保留两级：`##` 保留 10 个大节（含结语与资料卡），`###`（三个转折点、五条质疑）降级成 `##` 下的加粗首行。

## 八、自动发布脚本

`scripts/wechat-draft.mjs` 把上面第三、四、五节的排版规则全部自动化，直接调微信官方接口写进**草稿箱**，再由人在后台点发布。

```bash
npm run wechat:draft              # 只生成本地预览，不联网
npm run wechat:draft -- --publish # 上传封面 + 写入公众号草稿箱
npm run wechat:draft -- --check   # 只校验凭据与 access_token
```

产物在 `wechat/out/`（已 gitignore）：`preview.html` 是 414px 宽的本地预览页，`content.html` 是最终要提交的 HTML，`thumb.jpg` 是压到 64KB 以内的封面缩略图。

### 脚本做的排版动作

| 规则 | 实现 |
| --- | --- |
| 两张表 → 竖排卡片 | 读 `cards-day.md` / `cards-companies.md` 替换，内容与本文档第三节一致，可直接改这两个文件 |
| 外链全部清成纯文本 | 链接只保留文字，不留 href；站内互链换成"站内另一篇讲个人行动清单的《…》" |
| 加粗收敛 | 只保留含数字的加粗、整段只有一处加粗的收尾句、以及引用块内部的原话；其余去掉 |
| 引用分级 | 7 段做成带竖线的引用卡，其余降级成灰色普通段落 |
| 标题压到两级 | `##` → 带左侧竖线的大标题；`###` → 加粗首行 |
| 封面 | `cover-1-1.svg` → 900×900 JPEG，自动压到 ≤64KB（微信缩略图素材上限） |
| 正文长度 | 脚本会打印正文字数，公众号上限 20000 字 |

### 凭据与前置条件

1. 公众号后台「设置与开发 → 基本配置」拿 **AppID** 与 **AppSecret**，写进 `~/.config/wechat-publish/credentials.json`（本仓库不入库，也可留 `credentials.example.json` 的格式参考）：

   ```json
   { "appid": "wx...", "appsecret": "..." }
   ```

   或者用环境变量 `WECHAT_APP_ID` / `WECHAT_APP_SECRET`。**不要把 AppSecret 贴进聊天或提交进仓库。**

2. 同一页面把调用来源 IP 加进 **IP 白名单**（本机公网出口 IP：`47.115.229.74`）。不加会返回 `errcode 40164`。

3. 跑 `npm run wechat:draft -- --check` 验证凭据与 IP 白名单都通，再跑 `--publish`。

### 两条兜底路径

- **没有「发表」权限的未认证订阅号**：`draft/add` 仍然可用（写草稿箱，人工发布）；若某天接口返回 `errcode 48001`，改走 `material/add_news` 建素材 + `message/mass/send` 群发（未认证订阅号每天 1 次）。
- **接口报正文过长**：把「资料卡」整节移出正文，正文末尾留一句"完整出处见阅读原文"，正文里那 11 个 URL 就交给站内页面承载。

### 为什么不扫码登录后台

公众号后台是重 SPA + 强风控（扫码、验证码、设备指纹），用 headless Chrome 模拟登录既易坏又违反平台对脚本操作后台的约定；本机也没有任何浏览器。官方 API 一次配置就能长期用，而且有草稿箱这种"机器写、人点发布"的对称流程——机器干排版，人干判断。
