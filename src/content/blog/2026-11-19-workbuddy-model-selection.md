同一件活儿，在「快速」和「极致」两档上花掉的积分，不是同一个量级。

差多少？官方文档没给这张对照表，它只说了半句：消耗量＝模型 Token 定价 × 任务复杂度。另一半藏在更朴素的地方——每一轮对话，系统都要把当前上下文完整重发给模型一遍。

所以上下文越长，每一轮越贵。官方文档里有句话挺实在：**更大的窗口不会让模型变聪明，只会让每轮消耗成倍增加。**

这篇说清三件事：三档各自接什么活、那 14 个内置模型怎么挑，以及四个今天就能调的省积分开关。

## 一、模型选择器里有两件事，不是一件

WorkBuddy 的模型选择器里有两种东西混在了一起。

官方文档把它们分成两层：上面那排「快速 / 均衡 / 极致」是**第 1 层，模型模式**，定位是「按任务复杂度选择」；下面那排能直接点名的，是**第 2 层，内置模型**，文档单独用一张表列了 14 个。

一个是「这类活该用多强的算力」，一个是「具体用哪一家的模型」。文档分开写，读者很容易看成一件事。

文档没说这两者能叠加，所以按「选一个」来理解最保险：选模式是把调度权交给系统，直接点名模型是自己做主，积分按那个模型自己的定价扣。

![WorkBuddy 模型选择器：上方是快速、均衡、极致三档，下方是内置模型列表](/dist/img/wb-model-mode.png)

*官方文档《模型配置》里的模型选择示意图。*

## 二、三档分的不是强弱，是任务

官方表格写得很清楚：

- **快速模式**——简单、明确的任务，例如日常问答、格式转换、小段代码修改、文案润色。响应最快，消耗最低。
- **均衡模式**——绝大多数任务，例如写文档、分析数据、多文件代码改动。效果和速度兼顾，不确定选哪档时用它。
- **极致模式**——复杂任务，例如跨模块重构、多步骤推理、需要反复验证的分析。响应稍慢，消耗更高，但复杂任务下结果更稳定。

怎么落到自己手上的活儿，下面这段是我的判断，官方没这么写：

- 快速档：一次成型的小活。改错字、统一格式、把一段话翻译过来。
- 均衡档：结构固定、量不小的活。会议纪要、周报、数据分析、多文件改动。默认停在这儿。
- 极致档：错一次就要返工的活。终稿核对、跨文件重构、逻辑链条长的问题。

差多少钱？腾讯云开发者社区有一篇测算给了组系数——快速 0.21、均衡 0.65、极致 1.20，按「1 倍率≈1 积分/千 token」估算，一个 3.2 万 token 的标准任务，快速约 6.7 积分、均衡约 20.8、极致约 38.4。

换算下来，从快速升到均衡贵 3.1 倍，从均衡升到极致只贵 1.85 倍。

这个差距直接决定日常策略：停在均衡，把极致留给真正错不起的活儿。

要说清楚的是，这组系数出自第三方测算，作者自己写着「依据配置结构作出的判断，官方未逐条公示」，所以我拿它当参考，不当价目表。那篇文章里的模型清单还是 2026-10 的快照，和现在的官方表已经对不上。

## 三、14 个模型，其实只需要看三个标记

官方内置模型表的每一行，后面都跟着「图片输入」「思考模式」「推理模型」这样的能力标记。挑模型不用背 14 个名字，回答三个问题就够：

1. 要不要读截图、图表、扫描件？
2. 逻辑链条长不长？
3. 素材是不是超长文档？

按这三个问题筛完，还有两个事实值得单独记住。

**读图能力是分化的：14 个模型里只有 10 个支持图片输入。** 支持的是 Hy4 preview、Hy3、GLM-5.3、GLM-5.2、GLM-5v-Turbo、MiniMax-M3、MiniMax-m2.7、Kimi-K3、Kimi-K2.7-Code、Kimi-K2.6；另外 4 个不支持：GLM-5.3-Flash、GLM-5.1、Deepseek-V4-Flash、Deepseek-V4-Pro。让它读一张截图却选了这几个，得到的往往是一句「我看不到图片」。

**能调思考强度的只有 7 个。** Hy4 preview、Hy3、GLM-5.3、GLM-5.3-Flash、GLM-5.2、Deepseek-V4-Flash、Deepseek-V4-Pro 标的是「思考模式」；GLM-5.1、GLM-5v-Turbo、MiniMax-M3、MiniMax-m2.7、Kimi-K3、Kimi-K2.7-Code、Kimi-K2.6 标的是「推理模型」。文档里这是两种不同的标记，简单说就是前者你能调思考强度，后者是模型自带推理能力。

两件事叠起来，省事的答案就出来了：**GLM-5.3 和 GLM-5.2** 同时满足读图、可调思考、1M 上下文；**Deepseek-V4-Flash** 不读图，但 1M 且速度优先，适合纯文本的大文件处理。

剩下几个模型的定位，官方简介里写得很清楚，我直接照抄：

- Hy4 preview：混元新一代模型
- Hy3：混元思考模型，具有增强的推理能力
- GLM-5.3：GLM 新一代模型，支持 1M 上下文窗口
- GLM-5.3-Flash：GLM 新一代模型的快速版本
- GLM-5.2：1M 上下文，擅长长程任务
- GLM-5.1：能力均衡，适合日常使用
- GLM-5v-Turbo：原生多模态模型
- MiniMax-M3：原生多模态，擅长代码、智能体任务
- MiniMax-m2.7：能力均衡，适合日常使用，性价比高
- Kimi-K3：擅长处理复杂的长程自主任务，前端开发能力突出，在知识工作与科研推理上表现出色
- Kimi-K2.7-Code：多模态模型，面向编程场景优化
- Kimi-K2.6：多模态模型，适合日常任务
- Deepseek-V4-Flash：DeepSeek 旗舰模型，支持 1M 上下文窗口，速度优先
- Deepseek-V4-Pro：DeepSeek 旗舰模型，支持 1M 上下文窗口

模型清单在变。腾讯云企业版文档（2026-09-07 更新）里的内置模型表还是上一代（Auto、Hy3、GLM-5.2、GLM-5.1、GLM-5v-Turbo、MiniMax-M3、Kimi-K2.7-Code、DeepSeek V4 系列、Kimi-K2.6）。照着两三个月前的文章抄名单，大概率抄错。

## 四、积分怎么扣：先看乘号，再看减法

《积分说明》把一次消耗拆成两个因素：**模型 Token 定价**（高级模型单价更高）× **任务复杂度**（推理计算量和处理量更大）。

第三个乘数是上下文长度，前面说过了——每一轮都要重发一遍。

套餐这边，2026 年 7 月 1 日起国内个人版改成了三档：

- 体验版：免费，500 积分/月，模型调度写的是「Auto 模型调度（限免全模型可选）」
- 标准版：99 元/月，基础 2000 + 赠送 2000，每月实得 4000
- 高级版：199 元/月，基础 4000 + 赠送 5000，每月实得 9000
- 旗舰版：999 元/月，基础 20000 + 赠送 30000，每月实得 50000
- 加量包：1000 积分 / 50 元 / 有效期 1 个月，不支持退款，也不结转

两条容易漏的规则：

赠送积分自到账日起 1 个月内有效，积分按月发放、当月不结转。这一条的意思是，不用就等于没有，月底清零。

WorkBuddy 和 CodeBuddy 同一账号积分共享。加入 Buddy One 并关联账号之后，腾讯文档、ima、腾讯网盘里的 AI 积分，跟 WorkBuddy 是同一份余额——《Buddy One 积分使用说明》里的原话是「同一份积分余额，实时共享」。

这条对个人最要紧：你在 WorkBuddy 里随手开的一个长会话，花掉的是你在腾讯文档、ima 里同一份额度。

想看明细，客户端头像 → 设置 → 套餐与积分 只看得到套餐本身，逐条消耗记录得去官网个人中心 → 套餐与用量 查。

粗算一笔：按上面那组第三方系数估算，体验版的 500 积分，在均衡档上大约够二十来个 3.2 万 token 的大任务，或者几百次快速档的小问答。够不够，取决于你一天要问多少句「帮我把这段话改一下」。

## 五、省积分的四个开关，按这个顺序动手

### 1. 该开新会话就开新会话

官方《高效使用小技巧》里有一条叫「不同的任务，开不同的会话」，说每个会话可以当成一张独立工作台。它还补了更实用的一句：如果一个会话过长，WorkBuddy 开始「前说后忘」「越聊越跑偏」，就别硬撑，直接开新任务，把关键背景重新简洁说一遍，往往比在旧上下文里反复修补更有效。

长会话有两个代价。一是上下文越滚越长，每一轮都在为前面的历史付钱；二是模型被无关的历史带偏，返工又是一次输出。

### 2. 上下文档位：点输入框的「上下文用量」圆环

这是最容易被忽略的开关。点输入框里的圆环，弹出的面板底部能切档位：默认 / 适中 / 超长。

官方把这件事说得很直白：每一轮对话都会把当前上下文完整发送给模型，上下文越大，单轮消耗的积分就越多；窗口并非越大越好。

三条规则要记住：

- 档位越高，单轮积分消耗越大；
- 切换后立即保存，对话正在进行则从下一轮生效；
- 档位只对当前任务生效，换模型或新建任务后恢复为该模型的默认档位。

也就是说「设一次管全程」这件事不存在，长任务里得自己再切一次。官方的建议是保持默认档位，只在处理超长文档、或需要模型完整记住大量历史内容时才调大。

![上下文用量面板：上方显示各部分占用，底部切换档位](/dist/img/wb-model-context.png)

*上下文档位在输入框的「上下文用量」圆环里，切换只对当前任务生效。*

### 3. 经济模式：设置 → 智能体 → 经济模式

这里有个版本坑：原来模型面板里的「Max 模式」开关，已经搬到 设置 → 智能体 → 经济模式 了。个人版默认开启。

开启后，系统会在合适的时机自动压缩上下文，减少长对话里重复传输的内容；关闭后全程保留完整上下文、不做压缩，细节不丢，但长对话的积分消耗会明显增加。

官方建议保持开启，只在需要模型完整保留全部上下文时才关。版本升级不会覆盖你已有的选择。

![设置 → 智能体 → 经济模式](/dist/img/wb-model-economy.png)

*经济模式现在在「设置 → 智能体」里，不在模型面板里了。*

### 4. 思考强度：默认就好，长链任务再调

思考强度是模型给出答案前的推理投入，可选等级取决于模型自身支持的档位。强度越高，模型做的分析和自我检查越多，适合逻辑链条长、容易出错的活儿；强度越低，倾向直接作答，响应更快。

官方说「已默认选择适合绝大多数任务的强度，一般无需单独调整」，这话我同意，大多数人应该从不动它。

有个细节值得知道：会话标题的自动生成是轻量的辅助调用，无论你用哪个模型，都不会开启思考模式，标题出得更快，也省了这部分的 Token。

![思考强度设置](/dist/img/wb-model-thinking.png)

*思考强度在模型设置里，选项多少取决于模型支持几档。*

## 六、按任务查表

这一段可以直接照着做：

- 改格式、改错字、翻译一段话 → 快速模式
- 会议纪要、周报、数据分析、多文件改动 → 均衡模式（默认）
- 终稿核对、跨文件重构、长链条推理 → 极致模式
- 超长文档，或整个项目丢进去问 → GLM-5.3、GLM-5.2、Deepseek-V4-Pro 这类 1M 上下文的模型
- 读截图、图表、扫描件 → Hy4 preview、GLM-5.3、Kimi-K3、MiniMax-M3 等支持图片输入的模型，记得避开 DeepSeek V4 系列和 GLM-5.3-Flash
- 批量改写几十条文案 → 快速模式，或者直接点名轻量模型
- 写代码 → MiniMax-M3、Kimi-K2.7-Code，官方对这两个的定位分别是「擅长代码、智能体任务」和「面向编程场景优化」

遇到「读不了这个文件」，先别怀疑文件坏了。官方 FAQ 给的常见原因第一条就是「当前模型不支持对应文件类型」，处理办法是换一个支持图片或文档输入的模型。

## 七、几个坑

- 上下文档位只对当前任务生效。 以为设一次能管全程的，会在每个新任务上多付一笔。
- 模型下线会自动切换，但你的思考强度和上下文档位不跟着走。 官方规则是优先换同系列新模型（比如 Kimi-K3 下线换 Kimi 系列对应的新模型），没有对应的新模型就用系统默认模型，切过去之后思考强度和上下文窗口按新模型的默认值来。定时任务更明显：同系列没有新模型时，直接改用「快速」模式对应的默认模型。
- 自定义模型配不全会被置灰。 没填接口地址或 API Key 的，列表里点不动，真发请求会报错误码 4100。指向本机的 Ollama 不需要 API Key，不受影响。
- 接第三方模型的费用你自己付，不走 WorkBuddy 积分。官方专门有一条：自定义模型产生的全部费用由你直接付给第三方。
- **模型会堵。** 选择器里悬停模型能看到繁忙程度：空闲（绿）、轻微拥堵（橙）、极度拥堵（红）、不可用。极度拥堵的模型，列表里名字旁边直接有个红图标。官方建议换模型，繁忙程度仅供参考，不阻止你选。
- **网上的倍率表别全信。** 像 0.21 / 0.65 / 1.20 这类数字，都是第三方按客户端配置推算的，官方没有逐条公示，模型清单还是某个月的快照。

*模型列表里的红色图标表示这个模型此刻极度拥堵。*

## 八、自己接模型，什么时候值得

WorkBuddy 支持接第三方模型当底座，配置（含 API Key）只存在本地 `workbuddy/models.json`，不上传云端；WorkBuddy 只做通信链路，输入直达第三方模型。

三条路：

- **腾讯云 Token Plan**：兼容混元、MiniMax、Kimi、GLM 等，官方说是专为 AI 编程和 WorkBuddy 场景做的；另有 Coding Plan（腾讯云、智谱、Kimi 三家）。
- **本地 Ollama**：装完在本地监听 11434 端口，提供兼容 OpenAI 协议的接口。官方列的适用场景有三条——数据不出本机（金融、政企、内网合规）、零成本试用（不消耗 Token、不用付费 API Key，把硬件当算力）、离线可用。
- **自定义 API**：服务不在上面列表里，手填 URL、API Key 和模型名。

什么情况下值得折腾：材料涉敏、不能出本机；或者你本来就有 Token Plan / Coding Plan，额度别浪费。代价也清楚——算力自备、可用性和稳定性看第三方的脸色、费用自己盯着。

## 九、几句带走的

- 三档分的是任务类型。默认停在均衡，关键任务再上极致。
- 积分账单里波动最大的变量是上下文长度，档位系数只是其中一个乘数。
- 省积分有先后：新会话 → 上下文档位 → 经济模式 → 思考强度，最后才轮到降档。

我把三档模式、14 个内置模型的能力标记，以及按任务查档位的表，整理成了一份速查清单。

**回复关键词「选型」领取。**
